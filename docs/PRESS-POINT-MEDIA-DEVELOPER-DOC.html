PRESS POINT MEDIA - DEVELOPER HANDOFF DOCUMENT

Project Type: News platform + Public app + Admin app + Web dashboard
Status: Planning and development handoff

1. Project Overview

Press Point Media is a multilingual digital news and media platform designed for:

  • Public readers to consume news, videos, and e-paper
  • Admin and editors to manage content securely
  • A main admin to control access, roles, and publishing
  • A separate secure control app for admin workflows
  • A public-facing website for readers

Important architecture:

  • Public app = read-only
  • Control app = secure admin access
  • Web dashboard = admin access through browser
  • Backend API = central logic for auth, content, and permissions

3. Security Model

Core principle: Public app and control app must be completely isolated.

Security architecture:

  • Public app = read-only access
  • Control app = authenticated admin access
  • Web dashboard = authenticated admin access
  • Admin actions pass through backend API
  • Public app cannot access admin users, logs, role settings, or private content

Authentication model:

  • Firebase Authentication or JWT-based auth
  • Email/password login for admin
  • Optional MFA for main admin
  • Short-lived access tokens
  • Refresh token support
  • Auto logout after inactivity

Roles:

  • Main Admin: full access
  • Editor: content management in assigned categories
  • Moderator: review and approve content
  • Public User: read-only

Authorization rules:

  • Admin actions must be verified server-side
  • Public app never calls admin APIs
  • Editors cannot manage users or roles
  • Main admin manages user permissions
  • Public app only reads published content

6. Role-Based Permissions

Role Access
Main Admin Full control of content, users, roles, settings, and logs
Editor Add/edit assigned content, upload media, publish approved content
Moderator Review and approve content
Public User Read-only

Rules:

  • Main admin creates/removes editors
  • Editors cannot delete admin accounts
  • Public app cannot access admin APIs
  • Server-side checks must validate every role request

FIREBASE_API_KEY=...

Important:

  • Never commit .env files
  • Use HTTPS
  • Use server-side validation everywhere

16. Deployment Strategy

Recommended:

  • Website: Hostinger
  • API: Render / Railway / VPS
  • Database: Firebase Firestore
  • App distribution: APK or Play Store

Production flow:

  1. Build backend API
  2. Configure Firebase auth/database
  3. Deploy API
  4. Connect public app to public API
  5. Connect control app to admin API
  6. Deploy website
  7. Test all flows
  8. Launch
